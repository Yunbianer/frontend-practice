### 逐题复核

- 第 1 题（?. 与 ??）：答对。city 为 null 时 city?.length 短路返回 null，?? 兜底给出"未知城市"。
- 第 2 题（空断言 !）：答错。手写答案"4 程序还能走到这里吗"。实际运行：getPet() 返回 null，pet! 在运行时抛出 Unhandled exception: Null check operator used on a null value（q2.dart 第 5 行），程序当场中断，第二句 print 永远执行不到。分歧原因：没注意到函数返回值是 null，并且以为 ! 能把空值"变成"有值。! 的作用只是替你向编译器打包票，null 时照样炸。
- 第 3 题（命名参数）：内容全对（1/无、3/无、2/少辣）。实际输出格式是"鱼香肉丝 x1，备注：无"，命名参数与传入顺序无关，count 默认 1，note 缺省走 ?? 的"无"。
- 第 4 题（整除与取余）：全对，包括最难的 -17 ~/ 5 = -3。Dart 的 ~/ 是向零取整（截断），不是向下取整，所以 -3.4 变 -3 而不是 -4；% 结果符号跟被除数一致，17 % 5 = 2。
- 第 5 题（空安全 + 命名参数组合）：答错。手写答案"小林用的是备用卷长度4，小张用的是A卷，长度1"。实际运行：小林 用的是 A卷，长度 2；小张 用的是 备用卷，长度 0。分歧原因有两个：一是三元表达式方向记反了，pick(true) 走问号后面的分支返回 'A卷'，pick(false) 走冒号后面的分支返回 null（条件 ? 真值 : 假值）；二是字符串长度按字符个数算，'A卷' 是 2 个字符，'备用卷' 是 3 个字符，不是 4。

### 本轮结论

- 已掌握：?. 与 ?? 的短路逻辑、命名参数默认值与顺序无关、~/ 与 % 的运算规则。
- 待巩固：! 空断言遇到 null 的运行时报错行为；三元表达式 ? : 的分支方向；字符串 length 是字符个数。
